## Política de versiones

- Las Engineering Releases son internas y versionan hitos técnicos, no despliegues de producto.
- `Draft` identifica documentación o cambios aún no aprobados.
- `Approved` identifica un hito validado pendiente de su corte técnico.
- `Released` identifica una Engineering Release cerrada con tag Git y controles de calidad superados, cuando la dirección determine ese estado.
- Cada nueva release actualiza este historial, `CHANGELOG.md` y `RELEASE_NOTES.md`.
- Un tag de KYRUMA OS™ no modifica `main`, no publica una GitHub Release ni despliega a producción.
